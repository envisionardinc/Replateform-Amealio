# 03 — Source → Target Mapping (REQUIRED capabilities)

Mapping for every **REQUIRED** India-baseline capability (from the P1.2 [Capability Matrix](../india-baseline/14-CAPABILITY-MATRIX.md)). Design only — nothing implemented.

**Migration approach** legend: **REUSE** (take as-is) · **ADAPT** (wrap/config) · **REFACTOR** (restructure, same stack) · **REIMPLEMENT** (behavior-preserving rebuild on new stack) · **REPLACE** (new mechanism) · **DEPRECATE** (drop).

> Baseline stack change is fundamental: legacy backend is **FeathersJS + MongoDB (JS/TS)**; target is **NestJS + PostgreSQL/Prisma**. Therefore most backend capabilities are **REIMPLEMENT** (cannot reuse Feathers services in NestJS) with **business behavior preserved** per P1.2 acceptance criteria. Integrations are **ADAPT** (reuse provider SDKs behind new ports). Consumer frontend (React 18) is **REFACTOR→Next.js**; admin/merchant (React 16) is **REIMPLEMENT**. Legacy duplicates are **DEPRECATE**.

Repos: VD=`amealio-vendordashboard`, WEB=`amealio_web_app`, DASH=`amealiodashboardmvp-`.

## Notes
- **DEPRECATE** targets: legacy `user_cart`, legacy consumer ordering/experience flows (superseded by V2), denormalized `restaurantCard` (→ read model), duplicate `refund`/`resetSettlements` model, orphan `/waiters` service, unused `RedisAuthService`.
- **OPTIONAL/OWNER-DECISION** capabilities (promotions, wallet, reporting, celebrations/events/ticketing, ONDC, personalization) are mapped in [02](./02-DOMAIN-BOUNDARIES.md) but are **not** in the REQUIRED mapping above; they enter the mapping only when scoped in.
- Testing strategy per capability: behavior-parity tests against P1.2 acceptance criteria + a golden-path regression suite per journey ([16](../india-baseline/16-END-TO-END-BASELINE-JOURNEYS.md)); financial capabilities additionally require reconciliation tests. Detailed sequencing/validation: [10](./10-MIGRATION-SEQUENCE.md).
